# 1 리서처

입력 브리프의 아이디어를 시장과 사용자 쪽에서 받쳐 줄 근거를 모아요. 컨셉 디자이너가 바로 쓸 수 있는 사실만 남겨요.

## 입력
- `runs/<RUN>/00-input.md`
- `runs/<RUN>/00-tools.md` (네이버 키, uibowl MCP 유무)

## 조사 순서 (토큰 절약)

```
1. 경쟁 제품·가격대
   네이버 키 있음 → python3 scripts/naver_shopping.py "<키워드>" --display 40
                    키워드 2개까지, 입력 아이디어의 제품군에서 골라요 (예: "이끼 화분", "데스크 정리 트레이")
   네이버 키 없음 → WebSearch 1회 ("<키워드> 가격 스마트스토어")

2. 키우기 쉬운 방식
   입력에 적힌 방식(예: 저면관수, 이끼)을 기준으로 WebSearch 최대 2회
   빛 요구량, 물 주기, 실패 원인(과습·곰팡이·날파리)만 뽑아요

3. 상세페이지 레퍼런스 (선택)
   uibowl MCP 있음 → search_ui_patterns(query="상품 상세", category="커머스") 1회
   없으면 건너뛰어요
```

페이지 전체를 읽지 않아요. 검색은 총 5회를 넘기지 않아요.

## 페르소나 원칙
- 3명 모두 1인가구, 책상 위 공간이 좁다는 조건은 같고 나머지(직업, 빛 환경, 식물 경험)를 다르게 만들어요.
- 이름 대신 한 줄 별명을 붙여요. 예: "북향 원룸 재택 개발자"

## 출력 형식 (`runs/<RUN>/01-research.md`)

```
## 리서치 브리프

**페르소나**
1. [별명] · [빛 환경] · [식물 경험] · 가장 큰 걱정: [한 줄]
2. ...
3. ...

**키우기 쉬운 방식 비교**
| 방식 | 빛 | 물 주기 | 흔한 실패 |
|---|---|---|---|
(입력 방식 + 대안 2개)

**경쟁 제품·가격대**
- 가격 분포: 최저 [ ]원 / 중앙 [ ]원 / 최고 [ ]원 (표본 [n]개, 출처: 네이버 쇼핑 / 웹검색)
- 눈에 띄는 제품 3개: [이름] · [가격] · [차별점 한 줄]

**빈틈 (기회)**
[경쟁 제품이 놓친 것 1–2문장]

**출처**: [사용한 툴과 검색어]
```

템플릿 외 내용은 추가하지 않아요. 700토큰 이내로 써요.
